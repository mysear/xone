Central handoff (shared config/proto/registry/lib are intentionally not edited here):

* Pool.singleton_advanced tag 29; new profiles `uniswap-v4-advanced` / `pancake-infinity-cl-advanced`, family `singleton-advanced`, adapters `uniswap-v4/core-advanced-1` / `pancake-infinity-cl/cl-advanced-1` agreed with main.
* The state `protocol` stays the base name, e.g. `uniswap-v4`. Validate Pool currencies against state currencies and PoolID against `snapshot.manager + "/" + snapshot.pool_id`. The immutable key fee is state.key_fee, not snapshot.lp_fee.
* New `wire::SingletonAdvancedState` expected Rust fields: protocol String, currency0 String, currency1 String, key_fee u32, snapshot_block_hash Vec<u8> (32 bytes), snapshot Option<wire::SingletonClState>. Advanced to_proto/from_proto are implemented in both singleton.rs copies; they bypass the legacy no-hook wire validator and invoke the advanced validator.
* `Pool.validate()` should call advanced.validate(), require matching key/base protocol/currency identity and exactly one state family. Legacy profiles continue using legacy validators. New Pool literals made elsewhere need both central optional fields initialized.
* Config request: `evm::SingletonAdvancedReadConfig { State, TickWordRadius, MaxInitializedTicks, MaxSteps }`. State preconditions: protocol, currencies, immutable key fee, canonical block hash, snapshot manager/runtime SHA256/pool ID/hooks/parameters and core.tick_spacing. Static placeholder snapshot.lp_fee must equal key_fee. Dynamic LP/protocol placeholders may be 0; core snapshot data is fetched fresh. Use the passed canonical frame anchor, not an old config snapshot anchor.
* The read entrypoint validates identity and budgets before reading. It performs EIP-1898 eth_getCode/eth_call at one anchor, verifies manager runtime, collects live fees/core/bitmap/ticks and Infinity hook registration. It returns base typed state. Central adapter wraps it in the advanced Pool profile.
* Central math dispatch calls `singleton::quote_advanced_exact_in(state,input,direction)` and moves returned next_state into the next Pool. It returns the same amount_out/consumed_in/remaining_in plus swap_fee and protocol_amount. It may faithfully return amount_out=0; optimizer should reject zero-output routes.
* Snapshot block hash binds the starting authority. Virtual next-state during route simulation retains that origin anchor, as legacy virtual snapshots do. A real external dynamic update requires collection at a new block.
* Infinity single-bin quote is a separately exported core math primitive (`singleton::infinity_bin`), not an admitted Pool/profile and not a CL fallback. Its reserves/key/manager/block collection and tree traversal are not wired.
* Native currency: zero address permitted only as sorted currency0. Domain/parser/core math support it; native transfer/settlement and transaction construction are not reference-executed by this slice.
* Callback masks: V4 0xcc, Infinity CL 0xcc0. Any of those callback or return-delta flags is rejected. Missing/rejected callbacks are never modeled as no-op. No arbitrary hook VM/custom accounting/per-swap fee override claim.
